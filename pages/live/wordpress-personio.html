Wie verbindet man WordPress mit Personio?
360VIER bindet Personio an WordPress-Karriereseiten an, für Unternehmen, die Stellen im eigenen Design und auf eigenen URLs zeigen wollen. Die Stellen kommen über den XML-Feed von Personio und liegen in WordPress als eigener Beitragstyp. Bewerbungen übergibt ein Formular auf der Website per Recruiting API an Personio. So arbeitet die Karriereseite von 360vier.de mit dem Beitragstyp personio_job, gefiltert nach Abteilung und Standort.

Personio-Stellen auf der WordPress-Karriereseite: drei Wege

Ob Verlinkung reicht oder Stellen eigene Seiten bekommen, entscheidet vor allem eins: Sollen Bewerberinnen und Bewerber auf eurer Website bleiben und die Stellen über eure Domain gefunden werden?

Personio-Karriereseite verlinken oder einbinden

Personio stellt eine eigene Karriereseite bereit, auf die die Website verlinkt oder deren Stellenliste sie einbindet. Das reicht bei wenigen offenen Stellen. Grenze: Die Bewerbung findet bei Personio statt, die Stellen stehen nicht als eigene Seiten auf eurer Domain.

Middleware mit n8n oder Make

Passt, wenn neue Stellen zusätzlich an Slack, LinkedIn oder einen Newsletter gehen sollen. n8n liest den XML-Feed in festen Abständen und verteilt Änderungen. Grenze: Für die Website braucht es trotzdem eine Ablage in WordPress, und Bewerbungsunterlagen sind in einer Middleware ein Datenschutzthema.

Stellen als eigener Beitragstyp

Nötig, wenn Stellen als indexierbare Seiten im Design der Website erscheinen und Bewerbungen über ein eigenes Formular laufen. 360VIER baut einen Beitragstyp, den Abgleich mit dem XML-Feed und auf Wunsch die Übergabe an die Recruiting API. Mehr dazu unter API-Integrationen.

Welche Daten zwischen Personio und WordPress fließen

Die Richtung ist klar verteilt: Stellen kommen aus Personio, Bewerbungen gehen dorthin zurück. Bewerberdaten bleiben nicht dauerhaft in WordPress, sie gehören nach der Übergabe in Personio.

  • Stellenanzeigen: mit Titel, Abschnitten der Anzeige, Beschäftigungsart, Abteilung und Standort, zeitgesteuert oder auf Knopfdruck abgeglichen.
  • Abteilungen und Standorte: als WordPress-Taxonomien, damit die Karriereseite filtern kann.
  • Sprachfassungen: Deutsch und Englisch getrennt über den Sprachparameter des Feeds.
  • Entfernte Stellen: gehen beim nächsten Abgleich auf der Website offline.
  • Bewerbungen: von WordPress nach Personio, mit Pflichtfeldern, Anschreiben und Dokumenten.

XML-Feed oder Personio API: welche Schnittstelle braucht ihr?

XML-Feed für veröffentlichte Stellen

Der Feed liegt unter https://{konto}.jobs.personio.de/xml, standardmäßig auf Deutsch, mit ?language=en auf Englisch. Ihr aktiviert ihn in Personio unter Einstellungen › Recruiting › Karriereseite. Er ist öffentlich und verlangt TLS 1.2.

Was das für euch bedeutet: Für die Anzeige der Stellen braucht ihr keine Zugangsdaten. Der Abschnitt „Über uns“ fehlt im Feed und wird auf der Website gepflegt. Webhooks gibt es nicht, WordPress fragt den Feed in festen Abständen ab.

Recruiting API für Bewerbungen

Bewerbungen nimmt POST https://api.personio.de/v1/recruiting/applications an. Pflichtfelder sind first_name, last_name, email und job_position_id. Dokumente werden vorher hochgeladen und über ihre uuid verknüpft.

Was das für euch bedeutet: Bewerbungen landen nicht mehr im Postfach, sondern direkt beim richtigen Prozess in Personio. Wichtig: Die job_position_id muss beim Abgleich in WordPress gespeichert werden, sonst lässt sich eine Bewerbung keiner Stelle zuordnen.

Zugangsdaten, Token und Limits

Die API verlangt ein Token im Authorization-Header und die Personio-ID des Unternehmens in X-Company-ID. Client-ID und Secret entstehen in Personio auf der Seite „API Credentials“. Ein Token gilt 24 Stunden, der Auth-Endpunkt erlaubt 60 Anfragen pro Minute.

Was das für euch bedeutet: Die Zugangsdaten liegen nur auf dem Server, nie im Browser. Die lesenden Recruiting-Endpunkte der API v2 für Bewerbungen, Kandidaten und Stellen sind seit 2026 allgemein verfügbar und eignen sich für Auswertungen.

Ein KI-Agent beantwortet Bewerberfragen mit den Personio-Stellen

Auf der Karriereseite beantwortet ein KI-Chatbot Fragen mit den aktuellen Stellendaten: Welche Stellen gibt es in Köln, welche sind in Teilzeit möglich, welche Erfahrung wird erwartet. Er verweist auf die passende Anzeige und das Bewerbungsformular.

Intern bereitet ein Agent neue Stellen aus Personio als Entwurf für einen LinkedIn-Beitrag oder einen Newsletter-Abschnitt auf, etwa für den Versand über Brevo. Bewerberdaten bleiben in Personio, der Agent arbeitet nur mit veröffentlichten Anzeigen.

Ablauf: Personio-Anbindung für eure Karriereseite

Personio und WordPress bei 360VIER und ABG

Unsere eigene Karriereseite zeigt Stellen aus Personio über den Beitragstyp personio_job und einen Listen-Block im 360VIER-Theme. Je Stelle speichert WordPress Personio-ID, Sprache, Bewerbungslink, Abschnitte der Anzeige und den Zeitpunkt des letzten Abgleichs. Auf der Stellenseite steht ein eigenes Bewerbungsformular.

Für die ABG FRANKFURT HOLDING werden Stelleninserate über die Schnittstelle eines Drittanbieters ausgespielt. Im Relaunch hat 360VIER Inhalte und Formularfelder an den neuen Styleguide angepasst (Case ABG FRANKFURT HOLDING).

Gerade Kanzleien gewinnen Bewerberinnen und Bewerber über die eigene Website, mehr dazu unter Websites für Kanzleien. Umsetzung und Betrieb übernehmen unsere WordPress-Agentur und die WordPress-Wartung. Weitere Systeme: WordPress mit HubSpot verbinden und die Übersicht Integrationen.

Häufige Fragen zu Personio und WordPress

Gibt es eine Personio-API für Stellenanzeigen?

Ja, aber für die Anzeige auf der Website nutzt man meist den XML-Feed. Er liefert alle veröffentlichten Stellen ohne Anmeldung, auf Deutsch oder Englisch. Daneben nimmt die Recruiting API v1 Bewerbungen an, die API v2 liefert lesend Stellen, Bewerbungen und Kandidaten.

Kann ich die Personio-Karriereseite in WordPress einbinden?

Ja, auf zwei Arten. Ihr verlinkt die Karriereseite von Personio oder bindet die Stellenliste ein, dann bleibt die Bewerbung bei Personio. Oder WordPress übernimmt die Stellen als eigene Seiten im Design der Website. Das ist aufwendiger, bringt aber eigene URLs für jede Stelle, die Google indexieren kann.

Kostet die Personio API extra?

Der XML-Feed für veröffentlichte Stellen ist frei zugänglich und braucht keine Zugangsdaten. Für die Recruiting API legt ihr in Personio API-Zugangsdaten an. Ob euer Personio-Tarif sie enthält, klärt ihr mit Personio. Aufwand entsteht vor allem bei der Entwicklung der Anbindung auf WordPress-Seite.

Wie aktuell sind die Stellen auf der Website?

So aktuell wie der letzte Abgleich. Der XML-Feed meldet Änderungen nicht von sich aus, WordPress fragt ihn deshalb in festen Abständen oder auf Knopfdruck ab. Entfernte Stellen gehen beim nächsten Durchlauf offline. Für eine neue Stelle, die sofort online sein soll, startet ihr den Abgleich von Hand.
Was passiert mit Bewerberdaten und der DSGVO?

Sie sollten nicht dauerhaft in WordPress liegen. Sauber ist, Bewerbungen an Personio zu übergeben und die Formulardaten danach auf der Website zu löschen. Die Datenschutzhinweise im Formular und die Löschfristen stimmt ihr mit eurer Datenschutzberatung ab.

Werden Personio-Stellen bei Google gefunden?

Als eigene Seiten auf eurer Domain ja, wie jede andere Seite der Website. Dafür braucht jede Stelle eine eigene URL mit Titel, Beschreibung und Standort, wie es der Beitragstyp in WordPress liefert. Eine eingebettete Liste oder ein Link auf die Personio-Karriereseite stärkt dagegen nicht eure Domain.

Was passiert bei einem Update von Personio?

In der Regel nichts Sichtbares. Der XML-Feed ist seit Jahren stabil, Personio hat aber schon die Adresse der Karriereseite umgestellt und ältere TLS-Versionen abgeschaltet. Die Recruiting API entwickelt Personio in Version 2 weiter. Eine eigene Anbindung gehört deshalb in die Wartung, mit Blick auf das Changelog.
