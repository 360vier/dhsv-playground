WordPress-MCP-Server: MCP Adapter, Middleware oder eigenes Plugin

Ein MCP-Server legt fest, welche Werkzeuge eine KI in WordPress aufrufen darf und unter welchem Benutzer. Drei Wege führen dorthin:

MCP Adapter von WordPress.org

Das offizielle Plugin macht Abilities, die Plugins über die Abilities API registrieren, für MCP-Clients nutzbar, und bringt einen Standard-Server mit. Das reicht für Tests und interne Prototypen. Grenze: Das Projekt nennt sich selbst experimentell und stellt nur bereit, was Plugins als Ability anmelden.

Middleware mit n8n

Passt, wenn ein Agent feste Abläufe anstoßen soll, etwa „Beitrag aus Briefing anlegen, danach Nachricht an die Redaktion“. n8n spricht die WordPress-REST-API an und kann selbst als MCP-Server auftreten. Grenze: eigene Zugangsdaten, und jede neue Funktion ist ein neuer Ablauf.

Eigenes MCP-Plugin

Nötig für eigene Beitragstypen, Metafelder, Mehrsprachigkeit mit WPML oder einen Freigabeprozess. 360VIER baut ein MCP-Plugin mit eigenen Werkzeugen, OAuth-Anmeldung und Rechten, die an die WordPress-Rollen gekoppelt sind. Mehr zum Prinzip: API-Integrationen.

Was darf ein KI-Agent über WordPress MCP?

So viel, wie der Server freigibt. Die Rechte hängen am WordPress-Benutzer, mit dem sich der Client anmeldet, und an den Werkzeugen, die der Server anbietet. 360VIER richtet Server so ein, dass die KI Entwürfe anlegt und ändert, die Veröffentlichung aber ein Mensch auslöst. Löschende Werkzeuge bleiben abgeschaltet.

Jede Änderung läuft unter einem eigenen Benutzer und bleibt in den Revisionen nachvollziehbar. Das entspricht den Grundsätzen in unserem AI Manifest.

  • Beiträge und Seiten: lesen, suchen, als Entwurf anlegen und überarbeiten.
  • Metadaten: SEO-Titel, Beschreibungen und eigene Felder lesen und setzen, etwa für Rank Math.
  • Medien: Bilder hochladen und Alternativtexte pflegen.
  • Taxonomien: Kategorien und Schlagwörter auflisten und zuordnen.
  • Website-Informationen: Beitragstypen, Taxonomien und Einstellungen als Kontext, nur lesend.

Abilities API und MCP Adapter: der technische Stand in WordPress

Abilities API im WordPress-Kern

Seit WordPress 6.9 registrieren Plugins Fähigkeiten mit wp_register_ability(), jeweils mit Ein- und Ausgabeschema und einer permission_callback. Per REST sind sie unter wp-abilities/v1 erreichbar.

Was das für euch bedeutet: Funktionen eurer Website lassen sich einheitlich beschreiben und für KI-Clients freigeben. Weil die API Teil des Kerns ist, wird sie mit jedem WordPress-Update gepflegt.

MCP Adapter und Standard-Server

Der MCP Adapter (Version 0.7.0, Oktober 2026) setzt auf der Abilities API auf, unterstützt die MCP-Spezifikation vom 28.07.2026 und verlangt WordPress 6.9 und PHP 7.4. Im Standard-Server erreicht der Client freigegebene Abilities über drei Meta-Werkzeuge: finden, beschreiben, ausführen.

Was das für euch bedeutet: Sichtbar wird nur, was mit meta.mcp.public freigegeben ist. Für Tests reicht das. Eigene Server bieten Abilities direkt als Werkzeuge an, was Agenten die Arbeit erleichtert.

Anmeldung mit OAuth 2.1

Die MCP-Spezifikation macht Autorisierung optional. Wer sie über HTTP anbietet, soll OAuth 2.1 nutzen: Der Server veröffentlicht Protected Resource Metadata (RFC 9728), Clients nutzen PKCE und schicken das Token in jedem Request im Authorization-Header.

Was das für euch bedeutet: Ohne gültiges Token beantwortet ein geschützter Server keine Anfrage. Der MCP Adapter selbst arbeitet mit WordPress-Anwendungspasswörtern über den Proxy @automattic/mcp-wordpress-remote, für Produktivsysteme setzt 360VIER auf OAuth.

Claude und ChatGPT anbinden

Claude bindet entfernte MCP-Server als benutzerdefinierte Connectors ein, in allen Tarifen. In Team- und Enterprise-Konten fügen Owner den Connector hinzu, danach meldet sich jedes Mitglied selbst an. ChatGPT unterstützt eigene MCP-Server über den Entwicklermodus.

Was das für euch bedeutet: Claude verbindet sich aus der Cloud von Anthropic, nicht vom eigenen Rechner. Eine Staging-Seite hinter VPN ist dann nicht erreichbar. Schreibende Werkzeuge sollten nur Entwürfe erzeugen, weil die Recherche-Funktion Werkzeuge ohne erneute Bestätigung aufrufen kann.

Redaktion mit Claude und ChatGPT: Entwürfe per MCP, Freigabe in WordPress

Über den MCP-Server arbeitet die Redaktion aus Claude oder ChatGPT heraus in WordPress. Der Agent legt aus einem Briefing einen Entwurf an, setzt Titel und Meta-Beschreibung, ordnet Kategorien zu und lädt Bilder mit Alternativtext hoch.

Er prüft bestehende Seiten auf fehlende Metadaten oder veraltete Aussagen und schreibt die Korrektur als Entwurf zurück. Wie Agenten mit Rechten, Freigaben und Protokoll gebaut werden, beschreibt agentische KI. Abläufe über mehrere Systeme, etwa mit Brevo oder HubSpot, gehören zur KI-Prozessautomatisierung.

Wie 360VIER WordPress MCP auf der eigenen Website betreibt

360VIER betreibt auf der eigenen WordPress-Installation einen MCP-Server mit eigenem Plugin. Es stellt Werkzeuge wie get-post, list-posts, create-post, update-post, set-post-meta, upload-media und list-terms bereit. Die Anmeldung läuft über OAuth mit PKCE und getrennten Rechten für Lesen, Schreiben und Administration.

Die Arbeitsweise: Entwürfe per KI, Veröffentlichung nur nach Freigabe. Unseren Newsletter-Entwurf für Brevo legt ebenfalls ein MCP-Werkzeug an. Wie KI-Werkzeuge über Schnittstellen große Datenbestände bewegen, zeigt die Migration für BÜRGER: 150 Boards und über 20.000 Aufgaben von Monday nach ClickUp (Case BÜRGER).

Kunden der WordPress-Wartung bekommen Zugriff für eigene KI-Agenten über MCP. Eigene Anwendungen mit KI entstehen in der KI-Softwareentwicklung, Websites in der WordPress-Agentur. Alle Systeme: Integrationen.

Häufige Fragen zu WordPress MCP

Was ist ein WordPress-MCP-Server?

Ein MCP-Server ist eine Schnittstelle nach dem Model Context Protocol, über die KI-Anwendungen Werkzeuge einer Website aufrufen. Bei WordPress sind das etwa „Beitrag lesen“, „Entwurf anlegen“ oder „Bild hochladen“. Der Server legt fest, welche Werkzeuge es gibt und welcher Benutzer mit welchen Rechten dahintersteht.

Gibt es einen offiziellen MCP-Server für WordPress?

Ja. Der MCP Adapter ist ein offizielles Plugin von WordPress.org und baut auf der Abilities API auf, die seit Version 6.9 im Kern steckt. Im Oktober 2026 liegt er in Version 0.7.0 vor und gilt weiterhin als experimentell. Für Produktivsysteme solltet ihr Rechte, Anmeldung und Protokollierung selbst prüfen.

Wie verbinde ich Claude mit WordPress?

Über einen benutzerdefinierten Connector in Claude, der auf die Adresse eures MCP-Servers zeigt. Claude meldet sich per OAuth an, danach stehen die freigegebenen Werkzeuge im Chat bereit. Der Server muss aus dem Internet erreichbar sein, weil Claude sich aus der Cloud von Anthropic verbindet.

Funktioniert WordPress MCP auch mit ChatGPT?

Ja. ChatGPT unterstützt eigene MCP-Server über den Entwicklermodus. Der Server bleibt derselbe wie für Claude, Rechte und Werkzeuge gelten für beide Clients. Welche Tarife und Schreibaktionen ChatGPT gerade erlaubt, prüft ihr vor dem Einsatz in der Hilfe von OpenAI.
Was passiert bei einem WordPress-Update?

Die Abilities API wird als Teil des Kerns mitaktualisiert. Der MCP Adapter und die MCP-Spezifikation ändern sich noch, Version 0.7.0 bedient ältere Clients über das Schema vom November 2025 weiter. Ein eigenes MCP-Plugin gehört deshalb in die reguläre Wartung, mit Test der Werkzeuge nach jedem Update.

Ist meine Website dann für jeden KI-Dienst offen?

Nein. Ohne gültiges Token beantwortet ein geschützter MCP-Server keine Anfrage. Nach der Spezifikation muss jeder Request ein Token tragen, das der Server für sich selbst ausgestellt hat. Zusätzlich lassen sich Werkzeuge einzeln abschalten und Zugriffe auf bestimmte Benutzer und Rollen begrenzen.

Kann ein KI-Agent auch WooCommerce oder eigene Beitragstypen bearbeiten?

Ja, wenn der Server dafür Werkzeuge anbietet. Eigene Beitragstypen, Metafelder oder WPML-Sprachfassungen bildet der Standard-Server des Adapters nur ab, soweit Plugins sie als Ability anmelden. Ein eigenes MCP-Plugin beschreibt sie gezielt und koppelt die Rechte an die passende WordPress-Rolle.
